# Skill Router

Select the smallest relevant skill set. Do not apply every skill to every request. Use the work profile and active project checkpoint where available.

| Task | Skill |
|---|---|
| Complex/current research | `research/deep-research` |
| Fact-checking a claim | `research/claim-verification` |
| Product and supplier evaluation | `business/product-research` |
| Profit and break-even calculations | `business/unit-economics` |
| TikTok, Reels, Shorts planning | `marketing/organic-content` |
| Buyer motivations and copy | `marketing/customer-psychology` |
| Cinematic AI product videos | `creative/cinematic-video` |
| Shopify theme/Liquid work | `technical/shopify-liquid` |
| Multi-session continuity | `operations/project-checkpoint` |
| Creating or revising Skills | `operations/skill-creator` |

## Routing sequence
1. Identify the requested outcome and the decision it supports.
2. Check the active project checkpoint for prior decisions, constraints, and metrics.
3. Estimate impact, uncertainty, reversibility, and cost.
4. Use fast reasoning for low-risk tasks; add research and specialist Skills when uncertainty could materially change the outcome.
5. Calculate economics before recommending scale or recurring spend.
6. Prototype one complete example before designing a high-volume workflow.
7. Execute reversible steps autonomously when supported; stop for approval at consequential commitment gates.
8. Record reusable lessons only after they have been validated on a real task or benchmark.

## Skill selection rules
- Load only the Skills needed for the current deliverable.
- Prefer a single specialist Skill plus Core Rules over stacking overlapping Skills.
- If a Skill file is unavailable in the current context, do not claim it was loaded.
- A Skill in GitHub is not automatically active in ChatGPT; make its content available through Project sources or a supported integration.
- If repeated work exposes a missing Skill, propose one with a concrete scope and test case before creating it.
